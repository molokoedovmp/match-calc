## 1. В чём цель работы

Компьютер хранит вещественные числа приближённо, в формате **с плавающей точкой**. У этого формата есть обычные конечные числа и специальные значения: положительная и отрицательная бесконечность, положительный и отрицательный нуль, а также `NaN`.

Цель работы — увидеть, как эти значения ведут себя в вычислениях и сравнениях, и понять, что происходит при округлении числа до **одинарной точности** (`float32`).

В варианте 2 нужно выполнить две части:

1. **Задание 1:** вычислить пять выражений со специальными значениями и проверить два сравнения.
2. **Задание 2:** выяснить, возможна ли ситуация `b == c`, но `a*b == a*c` ложно; отдельно разобрать пример `a = 2`, `b = 1`, `c = 1 + 2^(-k)`.

## 2. Что такое число с плавающей точкой

Очень грубо число хранится как **знак × значащие цифры × степень двойки**. Например, число 1,5 в двоичной системе имеет вид `1.1₂`. В памяти для значащих цифр отведено конечное число бит, поэтому произвольное число хранится не всегда точно: его приходится округлять до ближайшего представимого значения.

В работе встречаются два формата:

| Формат | Что означает | Точность значащей части |
|---|---|---|
| `float64` | Двойная точность; используется в задании 1 | 53 двоичных значащих бита |
| `float32` | Одинарная точность; используется в задании 2 | 24 двоичных значащих бита |

У `float32` возле числа `1` соседние представимые числа — `1` и `1 + 2^(-23)`. Расстояние между ними равно `2^(-23)`, то есть примерно `0,0000001192092896`. Числа между ними округляются к одному из соседей.

### Специальные значения

| Запись | Значение | Что важно помнить |
|---|---|---|
| `inf` | Положительная бесконечность | Больше любого конечного числа |
| `-inf` | Отрицательная бесконечность | Отличается от `inf` знаком |
| `0.0` | Положительный нуль | При обычном сравнении равен `-0.0` |
| `-0.0` | Отрицательный нуль | Знак может влиять на результат некоторых операций |
| `nan` | «Не число» (`Not a Number`) | Даже `nan == nan` даёт `False` |

`NaN` означает, что операция не дала обычного численного результата, например `∞ / ∞` или `0 / 0`. В математике эти выражения не имеют одного определённого значения. `NaN` — способ представить такую ситуацию в вычислениях.

**Важно:** результаты с `inf` и `nan` ниже — правила компьютерного формата IEEE 754. Это не утверждение, что в обычной математике разрешено делить на нуль.

## 3. Почему в программе используется NumPy

Python сам по себе при делении обычного `float` на `0.0` выдаёт ошибку `ZeroDivisionError`. Для этой лабораторной нужно увидеть специальные результаты вычисления. Поэтому программа берёт числа типов `np.float64` и `np.float32` из библиотеки **NumPy**. С ними операции ведут себя по правилам IEEE 754 и возвращают, например, `inf` или `nan`.

Строка `import numpy as np` подключает библиотеку и задаёт короткое имя `np`.

Конструкция `with np.errstate(divide="ignore", invalid="ignore"):` временно скрывает ожидаемые предупреждения о делении на нуль и неопределённых операциях. **Она не меняет результат вычислений.** После выхода из блока обычное поведение предупреждений восстанавливается.

## 4. Задание 1: специальные значения

### Что нужно проверить и зачем

Нужно вычислить пять выражений и объяснить каждое. Это показывает, что результат зависит от сочетания бесконечности, нуля и их знаков. Также нужно проверить, как специальные числа работают в сравнении `==`.

В программе создаются три значения:

```python
inf = np.float64(np.inf)
zero = np.float64(0.0)
minus_zero = np.float64(-0.0)
```

`np.inf` — бесконечность. Запись `np.float64(...)` означает двойную точность. `minus_zero` действительно хранит отрицательный нуль, хотя при сравнении он равен положительному.

### Разбор результатов

| Выражение | Вывод программы | Почему |
|---|---|---|
| `inf / 0` | `inf` | По правилам формата получается положительная бесконечность. |
| `0 / inf` | `0.0` | Положительный нуль, разделённый на положительную бесконечность, остаётся положительным нулём. |
| `inf / inf` | `nan` | Для отношения двух бесконечностей нет одного численного ответа. |
| `-inf / (-0)` | `inf` | Оба операнда отрицательные; знак результата положительный. |
| `0 / (-0)` | `nan` | Это разновидность `0 / 0`, неопределённая операция. |

Затем программа проверяет два предиката. **Предикат** здесь — выражение, ответом которого является `True` («истина») или `False` («ложь»):

```python
zero == minus_zero   # True
-inf == inf          # False
```

При численном сравнении `+0` и `-0` считаются равными. Положительная и отрицательная бесконечности различаются, поэтому `-inf == inf` ложно.

Знак нуля всё же не бесполезен. Например, в вычислениях с бесконечностью или при делении знаки могут влиять на знак результата.

## 5. Задание 2: равные множители и результат умножения

Здесь есть **два отдельных вопроса**. Их нельзя смешивать:

1. Возможно ли вообще для некоторых чисел `float32`, что `b == c` истинно, а `a*b == a*c` ложно?
2. Можно ли получить именно такую ситуацию для `a = 2`, `b = 1`, `c = 1 + 2^(-k)`?

### 5.1. Общий вопрос: да, возможно

Программа берёт:

```python
a = np.float32(np.inf)
b = np.float32(0.0)
c = np.float32(-0.0)
```

Сравнение `b == c` даёт `True`, потому что `+0` и `-0` численно равны.

Затем программа вычисляет оба произведения. При умножении бесконечности на нуль получается `NaN`:

```text
a*b = nan
a*c = nan
```

Кажется, что результаты одинаковые, ведь оба печатаются как `nan`. Но правило сравнения для `NaN` особое: `nan == nan` даёт `False`. Поэтому сравнение `a*b == a*c` тоже даёт `False`.

Итак, **ответ на общий вопрос — да**. Это пример не обычной ошибки округления, а особого поведения `NaN` при сравнении.

### 5.2. Пример с `a = 2`: подобрать `k` нельзя

Теперь берутся числа из условия:

```python
a = np.float32(2)
b = np.float32(1)
c = np.float32(1 + 2 ** (-k))
```

Запись `2 ** (-k)` в Python означает `2^(-k)`. Сумма сначала вычисляется, затем `np.float32(...)` сохраняет её в одинарной точности. При проверяемых `k = 23` и `k = 24` исходная сумма до перевода в `float32` вычисляется точно; важное округление происходит именно при переводе в `float32`.

| `k` | Что хранится в `c` после округления | `b == c` | `a*b` | `a*c` |
|---:|---:|:---:|---:|---:|
| 23 | `1.0000001192092896` | `False` | `2.0` | `2.000000238418579` |
| 24 | `1.0` | `True` | `2.0` | `2.0` |

Почему граница именно здесь:

1. Следующее число `float32` после `1` равно `1 + 2^(-23)`.
2. При `k = 23` величина `2^(-23)` равна целому шагу, поэтому `c` отличается от `1`.
3. При `k = 24` величина `2^(-24)` — половина шага. Число лежит ровно между двумя соседями и по правилу округления к ближайшему с выбором чётного (`round to nearest, ties to even`) превращается в `1`.
4. Тогда `b` и `c` в памяти одинаковы, и умножение каждого на `2` даёт одинаковый ответ `2`.

Для `k > 24` прибавка ещё меньше и `c` также округляется к `1`. Для целых положительных `k < 24` значение `c` отличается от `1`, то есть условие `b == c` уже не выполнено.

**Вывод по примеру:** подобрать `k`, при котором одновременно `b == c` и `a*b != a*c`, нельзя. Если два обычных конечных числа в `float32` уже равны, умножение их на одно и то же число `2` даст одинаковый результат. Особый общий пример выше работает именно из-за `NaN`.

## 6. Как устроена программа по шагам

Файл `lab3_variant2.py` короткий. Его логика такая:

1. `import numpy as np` — подключить числовые типы NumPy.
2. `np.float64(...)` — создать значения двойной точности для задания 1.
3. Первый `with np.errstate(...)` — выполнить деления, не печатая ожидаемые предупреждения. Внутри стоят пять `print(...)`, каждый выводит выражение и результат.
4. Два следующих `print(...)` — проверить `0 == -0` и `-inf == inf`.
5. `np.float32(...)` — создать числа одинарной точности для задания 2.
6. Второй `with np.errstate(invalid="ignore")` — вычислить `inf * 0` и `inf * (-0)`; оба результата — `nan`.
7. `left == right` — показать, что сравнение двух результатов `nan` ложно.
8. Цикл `for k in (23, 24):` — повторить расчёт сначала для `k = 23`, затем для `k = 24` и вывести результаты рядом.

`print(...)` только показывает результат на экране; на само вычисление он не влияет. `True` и `False` — значения логического типа: истина и ложь.

## 9. Частые вопросы на защите

**Что такое `float32`?** Число с плавающей точкой одинарной точности. У него 24 значащих двоичных бита, поэтому близкие числа иногда становятся одним и тем же после округления.

**Чем `float64` отличается от `float32`?** У `float64` больше бит для хранения значащей части: 53 против 24. Поэтому он обычно хранит числа точнее. В задании 1 использован `float64`, во втором — требуемый `float32`.

**Почему в работе вообще есть два нуля?** В формате хранится отдельный бит знака. Поэтому существуют `+0` и `-0`. При сравнении они равны, но знак может проявиться в других операциях.

**Что значит `NaN`?** Это специальный результат неопределённой численной операции, например `0 / 0` или `∞ / ∞`.

**Почему `nan == nan` ложно?** Так определены правила сравнения чисел с плавающей точкой. Проверка равенства с `NaN` не даёт `True`, даже если обе стороны отображаются как `nan`.

**Разве одинаковые произведения `nan` не должны быть равны?** На экране они выглядят одинаково, но оператор `==` для `NaN` возвращает `False`. Задание спрашивает именно про сравнение результатов.

**Зачем `np.errstate`?** Чтобы не засорять вывод ожидаемыми предупреждениями. Результат `inf` или `nan` от этого не меняется.

**Почему при `k = 24` `c` становится единицей?** Потому что прибавка `2^(-24)` равна половине шага `float32` около единицы. По правилу округления к ближайшему с выбором чётного результат — `1`.

**Почему нельзя подобрать `k` для `a = 2`?** Пока `c` отличается от `1`, условие `b == c` ложно. Как только `c` округляется до `1`, произведения на `2` становятся равными.

**Что самое важное не перепутать?** В общем случае ответ «да, возможно» из-за `NaN`. В примере `a = 2`, `b = 1`, `c = 1 + 2^(-k)` ответ «нет, подходящего `k` не существует».
