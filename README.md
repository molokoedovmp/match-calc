## 1. Цепная дробь и подходящие дроби

Обычная дробь — отношение целых чисел, например 13/34.
Цепная дробь записывает число через вложенные деления:

```text
[c0; c1, c2, ...] = c0 + 1/(c1 + 1/(c2 + ...))
```

Для 13/34 коэффициенты равны `[0; 2, 1, 1, 1, 1, 2]`.
Они получаются делением с остатком:

```text
13 = 0*34 + 13
34 = 2*13 + 8
13 = 1*8 + 5
 8 = 1*5 + 3
 5 = 1*3 + 2
 3 = 1*2 + 1
 2 = 2*1 + 0
```

Если останавливать запись на разных коэффициентах, получаются подходящие
дроби — последовательные рациональные приближения числа.
Например, `[0;2] = 1/2`, а `[0;2,1] = 1/(2+1/1) = 1/3`.

В `convergents` числители и знаменатели вычисляются по формулам:

```text
p[k] = c[k]*p[k-1] + p[k-2]
q[k] = c[k]*q[k-1] + q[k-2]
```

Начальные значения: p[-2]=0, p[-1]=1, q[-2]=1, q[-1]=0.
Функция использует `yield`: отдаёт очередную пару «коэффициент, дробь»
и продолжает работу при следующем запросе.

В работе порядок дроби a/b определяется как `max(|a|, b)` для несократимой
дроби с положительным знаменателем. У 13/34 порядок 34.
В таблице печатаются только подходящие дроби меньшего порядка,
поэтому сама исходная дробь исключается. Начальная дробь 0/1 включена;
Python выводит её сокращённо как `0`.

Каждая дробь переводится в остаток по простому модулю 10007:

```text
a/b → a * b^(-1) mod 10007
```

`b^(-1)` — обратное по модулю: целое число, произведение с b которого
даёт остаток 1. Например, `2*5004 = 10008`, то есть остаток равен 1.
Поэтому 1/2 представляется остатком 5004.
В Python обратное вычисляет `pow(b, -1, modulus)`.

| Дробь | Порядок | Остаток | Абсолютная ошибка относительно 13/34 |
|---|---:|---:|---|
| 0/1 | 1 | 0 | 13/34 |
| 1/2 | 2 | 5004 | 2/17 |
| 1/3 | 3 | 3336 | 5/102 |
| 2/5 | 5 | 8006 | 3/170 |
| 3/8 | 8 | 3753 | 1/136 |
| 5/13 | 13 | 4619 | 1/442 |

В этом примере ошибки последовательно уменьшаются.
Модуль достаточно велик для границы 34: `2*34² = 2312 < 10007`.
Наибольшая допустимая граница по этому неравенству равна 70.
Порядок дроби и модуль — разные величины.

Округление здесь означает замену исходной рациональной дроби более простой
подходящей дробью. Это не округление десятичной записи до заданного числа
знаков и не перебор всех дробей с ограниченным знаменателем.

## 2. Скалярное произведение и точность

Скалярное произведение — сумма произведений соответствующих координат:

```text
(a1,a2,a3) · (b1,b2,b3) = a1*b1 + a2*b2 + a3*b3
```

**Исходные данные согласованы как учебный пример.** Задание ссылается
на векторы прошлой лабораторной, однако выполненный вариант 2 лабораторной
№ 4 содержал обращение матрицы Гильберта и не задавал векторов.
Поэтому здесь явно используются:

```text
a = (100000000, 1/3, -100000000)
b = (1, 1, 1)
точный ответ = 100000000 + 1/3 - 100000000 = 1/3
```

Порядок сложения фиксирован: слева направо. Это существенно для чисел
с плавающей точкой: при добавлении малого числа к большому часть разрядов
малого числа может потеряться. После вычитания большого числа утраченные
разряды не восстанавливаются. Это пример потери значащих цифр.

### Что сравниваем

- `float32`: 24 двоичных разряда значащей части для нормальных чисел,
  около 7 значащих десятичных цифр;
- `float64`: 53 разряда, около 16 значащих десятичных цифр;
- библиотека `mpmath`: длина двоичной мантиссы задаётся через
  `mp.workprec(bits)`.

32 и 64 — общее число бит формата, включая знак и показатель степени.
Поэтому их нельзя напрямую отождествлять с числом бит мантиссы.

`dot_float` явно переводит координаты и выполняет умножения и сложения
в выбранном типе NumPy. В `dot_mp` координаты заново создаются из
числителей и знаменателей внутри каждого контекста точности.
Уже округлённый `float` не используется как исходное число для mpmath.

Точный эталон вычисляется через `Fraction`, то есть пару целых чисел.
Критерий улучшения — строго меньшая абсолютная ошибка:

```text
|результат mpmath - 1/3| < |результат базового типа - 1/3|
```

Функция `dot_mp` переводит результат mpmath в точную рациональную дробь
его двоичного значения. Для этого используется внутренняя четвёрка `_mpf_`:
знак, целая мантисса, двоичный показатель, длина мантиссы.
Число равно `(-1)^sign * mantissa * 2^exponent`.
Поэтому при сравнении ошибок результат не округляется обратно до float64.
Это единственное место, использующее внутреннее представление библиотеки;
для обычной печати результат затем переводится во `float`.

Программа перебирает все значения `bits` от 2 до 100 по возрастанию
и останавливается при первом улучшении, отдельно для двух базовых типов.

| Вычисление | Результат примерно | Абсолютная ошибка примерно |
|---|---|---|
| float32 | 0 | 0.3333333333 |
| mpmath, 28 бит | 0.5 | 0.1666666667 |
| float64 | 0.3333333283662796 | 4.967054e-9 |
| mpmath, 54 бита | 0.3333333358168602 | 2.483527e-9 |

**Минимумы в исследованном диапазоне: 28 и 54 бита.**
Более ранние значения проверяются программой, а не пропускаются.
Результат 0.5 ещё довольно грубый, но его ошибка уже меньше ошибки нуля.
«Стало лучше» не означает «стало достаточно точно для любой задачи».
Эти минимумы относятся к выбранным векторам, порядку суммирования
и критерию; они не являются универсальными свойствами библиотеки.

`e-9` означает умножение на 10 в степени −9.
Числа в таблице округлены для показа, сравнение выполняется точными дробями.

## 3. Вариант 2 — сервер обрабатывает запрос

### Состояния и переходы

- `idle` — сервер свободен;
- `req` — получен запрос;
- `wait` — ожидание ответа;
- `ack` — ответ подтверждён.

Начальное состояние `idle`. Метка req истинна только в состоянии `req`,
метка ack — только в `ack`. Все четыре состояния достижимы.

| Состояние | Следующие до исправления | Следующие после исправления |
|---|---|---|
| idle | req | req |
| req | wait | wait |
| wait | ack, wait | ack |
| ack | idle | idle |

В каждом состоянии есть хотя бы один исходящий переход.
Изначально в `wait` можно либо ответить, либо снова остаться в `wait`.
Мы не задаём ограничения справедливости: бесконечно выбирать ожидание
разрешено моделью.

### Что означают формулы

`AG(req → EF ack)`:

> В любом достижимом состоянии с запросом существует путь,
> на котором когда-нибудь будет ответ.

`AG(req → AF ack)`:

> В любом достижимом состоянии с запросом на каждом пути
> когда-нибудь будет ответ.

- `A` — все пути;
- `E` — существует путь;
- `G` — всегда;
- `F` — когда-нибудь, в том числе прямо сейчас;
- стрелка означает «если ..., то ...».

Главная разница: возможность не означает гарантию.

### Как программа проверяет все пути

Не нужно перебирать бесконечные последовательности.
Используется вычисление множеств до неподвижной точки:

1. В начальное множество включается `ack`.
2. Для EF добавляются состояния, у которых **хотя бы один** переход
   ведёт в уже найденное множество.
3. Для AF добавляются состояния, у которых **все** переходы
   ведут в уже найденное множество.
4. Повторяем, пока множество перестанет меняться.

Это реализовано в `eventually`. `any` означает «хотя бы один»,
`all` — «все». Для конечной модели цикл завершается, поскольку множество
может увеличиться только на конечное число состояний.
Функция `reachable` отдельно обходит граф от `idle`.
В главном цикле обе формулы проверяются для всех достижимых состояний,
в которых истинна метка req.

До исправления:

```text
EF(ack) = {idle, req, wait, ack}
AF(ack) = {ack}
AG(req → EF ack) = True
AG(req → AF ack) = False
```

Почему AF не включает wait? Один из переходов wait ведёт обратно в wait,
которого ещё нет в множестве гарантированного достижения.
Так появляется возможность бесконечного ожидания.

Контрпример:

```text
idle → req → wait → wait → wait → ...
```

После удаления петли wait → wait:

```text
EF(ack) = AF(ack) = {idle, req, wait, ack}
обе формулы = True
```

После `req` теперь обязательно идёт `wait`, затем `ack`.
Это проверка учебной конечной модели, а не запуск сетевого сервера.

## 4. Что делает каждая функция

| Функция | Назначение |
|---|---|
| `convergents` | Получает коэффициенты цепной дроби и подходящие дроби |
| `dot_float` | Скалярное произведение в float32 или float64 |
| `dot_mp` | Скалярное произведение при заданной длине мантиссы mpmath |
| `reachable` | Находит достижимые состояния от начального |
| `eventually` | Находит множество EF или AF по одному алгоритму |
| `main` | Задаёт примеры, вызывает функции и печатает результаты |

Полезные записи Python:

- `Fraction(1, 3)` — точная дробь одна третья;
- `divmod(a, b)` — сразу частное и остаток целочисленного деления;
- `zip(a, b)` — пары соответствующих координат;
- `with mp.workprec(bits)` — временно задаёт точность вычислений;
- `set` — множество без повторений;
- `result | {...}` — объединение множеств;
- `graph[state]` — список следующих состояний;
- `break` — прекращает перебор после найденного первого улучшения;
- блок `if __name__ == "__main__"` запускает `main` при запуске файла.

## 5. Готовый текст защиты

В лабораторной работе номер пять я выполнил задания про подходящие
дроби и точность скалярного произведения, а для второго варианта
проверки моделей исследовал сервер с ожиданием ответа.

В первой части исходная дробь 13/34 раскладывается в цепную дробь
делением с остатком. По её коэффициентам рекуррентными формулами
строятся подходящие дроби меньшего порядка. Например, одна вторая,
одна третья, две пятых и далее. Для каждой дроби вычисляются её порядок,
ошибка относительно исходного числа и представление по модулю 10007.
При переводе в остаток числитель умножается на обратное к знаменателю
по модулю. Так округление к более простой дроби выполняется без
предварительного перевода исходных данных в приближённые float.

Во второй части используются согласованные учебные векторы:
сто миллионов, одна третья, минус сто миллионов и вектор из трёх единиц.
Точное скалярное произведение равно одной третьей.
Такой пример выбран, чтобы показать потерю значащих цифр:
при прибавлении маленькой дроби к большому числу её разряды теряются,
а последующее вычитание большого числа их не восстанавливает.

Я сравниваю float32, float64 и библиотеку mpmath с изменяемой длиной
мантиссы. Для каждого количества бит исходные координаты создаются
заново. Ошибки сравниваются с точным результатом через рациональные
дроби. Перебор от двух до ста бит показал, что первое строгое улучшение
относительно float32 достигается при 28 битах, а относительно float64
при 54 битах. Это результат для выбранных векторов и порядка сложения.

В модели сервера есть четыре состояния: свободен, запрос, ожидание
и ответ. Сначала из ожидания можно либо перейти к ответу, либо остаться
в ожидании. Поэтому ответ возможен, но не гарантирован:
существует бесконечный путь, который остаётся в ожидании.

Для проверки я вычисляю множества состояний EF и AF до неподвижной
точки. Для EF достаточно одного перехода в уже найденное множество,
для AF туда должны вести все переходы. Затем свойства проверяются
во всех достижимых состояниях с запросом.

До исправления формула возможности ответа истинна, а формула гарантии
ложна. Контрпример — свободен, запрос, ожидание и бесконечное повторение
ожидания. После удаления петли обе формулы становятся истинными.
Таким образом, увеличение точности помогает сохранить значащие цифры,
а формальная проверка отличает возможность завершения от его гарантии.

### Если нужно ответить очень коротко

Программа строит подходящие дроби и их остатки, сравнивает точность
скалярного произведения и проверяет учебную модель сервера.
В согласованном примере mpmath впервые точнее float32 при 28 битах
и float64 при 54 битах мантиссы. В модели сервера сначала ответ
возможен, но не гарантирован из-за петли ожидания. После удаления
петли ответ становится гарантированным на каждом пути.

## 6. Вопросы преподавателя

**Почему векторы учебные?** В предыдущем выполненном варианте были матрицы,
а не векторы. Использование отдельного примера согласовано и явно указано.

**Что такое подходящая дробь?** Результат обрыва цепной дроби на одном
из коэффициентов. В программе она получается рекуррентными формулами.

**Почему нет самой дроби 13/34 в таблице?** Требуются меньшие порядки,
а её собственный порядок равен 34. Коэффициенты полной дроби выводятся.

**Почему не просто 1/b?** По модулю нужно целое обратное число,
дающее остаток 1 при умножении, а не обычная вещественная дробь.

**Почему 28 бит дают 0.5 — это же неточно?** Его ошибка 1/6 меньше
ошибки нулевого результата float32, равной 1/3. Проверяется первое
улучшение, а не достижение произвольной высокой точности.

**Почему не всегда достаточно 25 и 54 бит?** Точность зависит от
конкретных данных и операций. Маленькое число может потеряться
при сложении с большим даже при нескольких добавленных разрядах.

**Как доказывается минимум?** Перебираются все целые длины от 2 до 100,
и берётся первое значение, у которого ошибка строго меньше базовой.

**Почему нельзя сравнивать только напечатанные цифры?** Они округлены
для показа. Внутри сравниваются точные рациональные значения ошибок.

**Что такое EF и AF?** EF — существует путь к цели, AF — все пути
когда-нибудь достигают цели. Здесь рассматриваются бесконечные пути.

**Почему наличие перехода wait → ack недостаточно?** Потому что
можно каждый раз выбирать другой переход wait → wait и не ответить никогда.

**Как проверялись бесконечные пути?** Вычислением конечных множеств
до неподвижной точки, а не ограниченным перебором числа шагов.

**Почему после исправления всё работает?** У wait остаётся только
переход к ack, поэтому после запроса ожидание не может повторяться бесконечно.

**Это настоящий сервер?** Нет, граф переходов учебной модели сервера.
