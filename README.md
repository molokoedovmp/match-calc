## Задание 1. Дроби по одному модулю

Обычная дробь заменяется целым числом — остатком по модулю простого числа p:

```text
a/b → a * b^(-1) mod p
```

Здесь b^(-1) — обратное число по модулю: произведение b * b^(-1)
должно давать остаток 1. Это не обычная десятичная дробь 1/b.
В Python обратное число вычисляет `pow(b, -1, p)`.

Например, при p = 101 обратное к 2 равно 51, потому что
2 * 51 = 102, а 102 % 101 = 1. Поэтому дробь 1/2 хранится как остаток 51.

Класс `Drob` содержит:

- `p` — модуль; в примерах используется простое число 101;
- `N` — порядок дробей Фарея, здесь 7;
- `value` — целый остаток;
- `farey` — дробь, восстановленная из остатка.

Сложение, вычитание и умножение выполняются над остатками.
При делении умножаем на обратный остаток. Методы `__add__`, `__sub__`,
`__mul__`, `__truediv__` позволяют писать обычные `a+b`, `a-b`, `a*b`, `a/b`.

Обратное преобразование выполняет `restore()`. Это вариант расширенного
алгоритма Евклида: делим с остатком и параллельно обновляем коэффициенты,
пока остаток не станет достаточно малым. Из него и коэффициента получается
числитель и знаменатель. `Fraction` используется только для представления
восстановленной дроби; сами четыре операции выполняются по модулю.

Границы допустимых дробей: |числитель| ≤ N, 1 ≤ знаменатель ≤ N,
числитель и знаменатель взаимно просты. Условие 2*N² < p гарантирует,
что две разные дроби из этих границ не имеют одинакового остатка.
При p = 101 максимальное подходящее N равно 7: 2*7² = 98 < 101.
Формула `isqrt((p-1)//2)` находит эту границу целочисленно.

Результаты при a = 1/2, b = 1/3:

| Действие | Ответ |
|---|---|
| a + b | 5/6 |
| a - b | 1/6 |
| a * b | 1/6 |
| a / b | 3/2 |

Все ответы находятся в допустимых границах и получаются точно.

**Псевдопереполнение:** 7 * 7 при том же модуле восстанавливается как -3/2.
Правильный ответ 49 вышел за границу N = 7. У 49 и -3/2 одинаковый остаток
по модулю 101, поэтому по одному остатку их нельзя различить.
Это ограничение метода. Для точных ответов нужно заранее выбрать достаточно
большой простой модуль, чтобы исходные дроби и все промежуточные результаты
оставались в границах. Например, для 7*7 подходит p = 5003, N = 50.
Если остаток вообще не соответствует допустимой дроби, программа выдаёт
понятную ошибку. Но псевдопереполнение может дать и другую допустимую дробь,
как в приведённом примере, поэтому автоматически обнаруживается не всегда.

## Задание 2. Обращение матрицы Гильберта

Для индексов с нуля H[i,j] = 1/(i+j+1). Например, при N = 3:

```text
1    1/2  1/3
1/2  1/3  1/4
1/3  1/4  1/5
```

`hilbert(n, dtype)` создаёт такую матрицу. Тип `np.float32` означает
одинарную точность — примерно 7 значащих десятичных цифр,
`np.float64` — двойную, примерно 16 цифр.

`gauss_jordan()` реализует метод Гаусса — Жордана:

1. Справа к H приписываем единичную матрицу: [H | I].
2. В текущем столбце выбираем наибольший по модулю элемент из оставшихся строк
   и переставляем его строку на место ведущей. Это уменьшает влияние округления.
3. Делим ведущую строку на ведущий элемент, чтобы получить единицу.
4. Вычитаем её с нужным множителем из остальных строк, обнуляя текущий столбец.
5. Повторяем для всех столбцов. Получаем [I | H^(-1)].

Готовая функция обращения матрицы не используется. NumPy нужен для массивов,
типов точности и проверочного умножения. В одинарной точности и построение H,
и обращение, и проверочное умножение выполняются с типом float32;
в двойной — с float64.

## Как оценивается ошибка

Вычисляем C = H * H^(-1). В точной арифметике C = I.

В столбцах `err32` и `err64` выводится max|C[i,j] - I[i,j]| — наибольшее
отклонение элемента произведения от нужного значения.
Это также относительная ошибка по максимальному элементу матрицы,
потому что max|I[i,j]| = 1 и деление на эту величину ничего не меняет.

Поэлементная относительная ошибка равна |получено - точно| / |точно|.
На диагонали точное значение равно 1, поэтому максимальная относительная
ошибка диагональных коэффициентов равна max|C[i,i] - 1|.
Она выводится в столбцах `rel_diag32` и `rel_diag64`.
Вне диагонали точное значение равно нулю: делить на него нельзя,
поэтому там учитывается абсолютная ошибка в общем показателе `err`.

В условии не указан численный порог резкой потери точности.
В программе выбран явный критерий: `err > 0.01`, то есть ошибка больше
1% относительно масштаба единичной матрицы. Это не утверждение о
поэлементной относительной ошибке нулевых элементов.

Результаты запуска на этом компьютере (полная таблица — в программе):

| N | err32 | rel_diag32 | err64 | rel_diag64 |
|---|---|---|---|---|
| 5 | 3.343e-03 | 1.953e-03 | 6.297e-12 | 1.244e-12 |
| 6 | 8.550e-02 | 3.248e-02 | 4.495e-10 | 8.536e-11 |
| 7 | 3.442e+00 | 1.201e+00 | 2.023e-08 | 8.731e-09 |
| 10 | 3.656e+02 | 1.580e+02 | 2.886e-03 | 1.228e-03 |
| 11 | 4.170e+02 | 1.443e+02 | 1.092e-01 | 4.619e-02 |
| 12 | 2.845e+02 | 9.182e+01 | 2.303e+00 | 2.830e-01 |

**При выбранном критерии первое N — 6 для float32 и 11 для float64.**
Если считать полной потерей точности ошибку больше 1, получаем N = 7 и N = 12.
Порог, способ выбора ведущего элемента и особенности вычислений влияют на
границу, поэтому эти числа относятся к данному алгоритму и запуску.
При другом окружении последние цифры таблицы могут отличаться.

Причина: матрица Гильберта плохо обусловлена. С ростом N даже небольшие
ошибки округления могут сильно изменить её обратную матрицу.
Двойная точность хранит больше цифр, поэтому потеря точности наступает позже.

## Что сказать на защите

- **Что сделано в первой части?** Дроби перевожу в остатки по простому модулю,
  выполняю четыре действия над целыми числами и восстанавливаю дроби.
- **Почему нет ошибок округления?** В первой части используются целые числа.
  Точность результата гарантируется только при соблюдении границ дробей Фарея.
- **Зачем переставлять строки?** Чтобы выбирать больший по модулю ведущий
  элемент и уменьшить влияние ошибок округления.
- **Как проверяется обратная матрица?** Умножаю исходную на найденную обратную
  и измеряю наибольшее отличие от единичной матрицы.
- **Почему не сравниваю числа через ==?** Из-за округления произведение может
  немного отличаться от единичной матрицы даже при хорошем результате.
- **Какой основной результат?** При пороге 0.01 точность резко теряется
  с N = 6 в одинарной и с N = 11 в двойной точности.
- **Связаны ли две части программы?** Это два отдельных задания: в первом
  модулярная арифметика, во втором по условию требуется арифметика с плавающей точкой.
